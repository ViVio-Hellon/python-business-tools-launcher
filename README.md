# 業務ツール統合ランチャー (business-tools-launcher)

4つの独立した業務Webツールを、1つの常駐ランチャーから選択・起動・切り替えできるようにします。

**4つのツールを1つへ統合するものではありません。** 独立したまま置いておき、起動と切り替えだけを引き受けます。

| 表示名 | リポジトリ | アプリID | 既定ポート |
|---|---|---|---|
| 日報 | `ViVio-Hellon/vba-daily-report-python-migration` | `nlm.nippou-tool` | 8733 |
| カレンダー | `ViVio-Hellon/vba-calendar-python-migration` | `nlm.line-calendar` | 8730 |
| 看板 | `ViVio-Hellon/vba-production-board-python-migration` | `nlm.kanban-system` | 8741 |
| 総合ツール | `ViVio-Hellon/python-web-tools` | `nlm.packaging-tool` | 8713 |

## 使い方

### 起動する

`Start.vbs` をダブルクリックします。画面下に細長いランチャーバーが出ます。

```
[日報] [カレンダー] [看板] [総合ツール]  ● 現在：日報        [設定] [v1.0.0] [終了]
```

［設定］の左に、状況に応じて2つ増えます。

- **［ツール停止］** … ツールが動いているとき。ランチャーは残したままツールだけ止めます
- **［詳細］** … 出せる案内があるとき（起動に失敗した理由など）

使いたいツールのボタンを押すと、そのツールが起動して**専用のブラウザー画面**が開きます。
別のボタンを押すと、その画面を閉じ、ツールを終了してから次のツールを起動します。
**ランチャーは切り替えても終了しません。**

### 業務ツールの画面は、ふだんのブラウザーと分けています

ランチャーが開くのは、アドレスバーもタブもない専用ウィンドウです。
利用者がふだん使っている Chrome / Edge のウィンドウやタブとは**別のプロファイル**で動くので、
切り替えのときに Google やメールのタブが閉じることはありません。

```
ふだんのブラウザー          ランチャーの画面
├─ Google                  └─ 日報
├─ メール                       ↑ 切り替えで閉じる
└─ その他
     ↑ ランチャーは触らない
```

画面だけを手で閉じると、バーに `現在：日報（画面を閉じました・まもなく終了します）` と出ます。

**各ツールは「誰も見ていなければ終了する」仕組みを持っている**ため、画面を閉じると数秒で
自分から終了します（実行中の処理があれば終わるまで待ちます）。続けて使うときは、
もう一度ボタンを押してください — まだ生きていれば画面だけ開き直し、すでに終了していれば
起動し直します。

Edge も Chrome も見つからない端末では、既定のブラウザーで開きます。
その場合は**切り替えのときに画面が自動で閉じない**ので、バーに手で閉じるよう案内が出ます。
`start_debug.bat --check` でどちらになるか確認できます。

### 最初にすること — 起動ファイルの場所を教える

インストール直後は、どのツールも「未設定」(ボタンが茶色)です。
**[設定]** を押し、各ツールの起動ファイルを **[参照]** から選んでください。
`start.bat` と `Start.vbs` のどちらも指定できます。

［設定］を開くには**管理者パスワード**が要ります。はじめて開くときに決めてください
（→ [管理者パスワード](#管理者パスワード)）。

```
[日報      ]  nlm.nippou-tool                      [使う] [削除]
[ C:\業務ツール\日報\start.bat            ] [参照]
ポート [8733]  起動引数 [--no-browser]  停止方法 [auto]
```

表示名はここで変えられます（「日報(A棟)」など）。使わないツールは［使う］を外せば、
消さずにバーから隠せます。

PCによって置き場所が違っていても、ここを変えるだけで動きます。コードを書き換える必要はありません。

- 4つ全部を入れる必要はありません。使うものだけ設定すれば、残りは「未設定」のままで構いません。
- `起動引数` の `--no-browser` は、**ツール側にブラウザーを開かせない**ための指定です。ランチャーが起動完了を確認してから専用の画面を開きます。

#### `start.bat` と `Start.vbs` のどちらを指定するか

**`start.bat` を推奨します。** 引数が届き、出力ログと起動失敗の戻り値も取れるためです。

| | `start.bat` | `Start.vbs` |
|---|---|---|
| `--no-browser` が届く | ○ (`%*` で転送) | **ツール側の作りによる** |
| ツールの出力ログ | ○ `tool_*.out.log` | × (pythonw にコンソールが無い) |
| 起動失敗の戻り値 | ○「戻り値 3」と表示 | × (即座に抜ける) |
| 画面を開くのは | **ランチャー**（専用ウィンドウ） | ツール側（ふだんのブラウザー） |

> `start.bat` は診断用の入口ですが、ランチャーから呼ぶときコンソールは出ません
> （非表示で起動し、末尾の `pause` も素通りします）。

**4つのツールの `Start.vbs` は引数を転送しません。** そのため `Start.vbs` を指定すると、
`--no-browser` が届かず、ツールが自分でふだんのブラウザーに画面を開きます。
その場合ランチャーは**自分の画面を開きません**（両方開くと画面が2枚になり、
作業状態を奪い合うため）。代わりに、切り替えのときランチャーからは閉じられない旨を表示します。

ランチャーは `Start.vbs` の中身を読んで引数を転送するかどうかを判定します。
転送しない組み合わせで保存しようとすると、保存前に確認が出ます。

### 起動・切り替えの進み具合

ツールが立ち上がるまでの数秒〜数十秒は、画面の中央に**進み具合の窓**が出ます。

```
日報 → 看板 に切り替えています
 ✓ 日報の画面を閉じる
 ✓ 日報を終了する
 ✓ 看板の起動ファイルを実行する
 ▶ 看板の準備ができるのを待つ
     アプリを準備中              ← ツールが知らせてくる準備の段階
 ・ 看板の画面を開く
 [■■□□□□□□ 動き続ける棒 ]
 12秒 (最大90秒まで待ちます)                 [隠す]
```

- すぐ終わる操作 (0.4秒未満) では出ません
- 起動し終わる・失敗すると自分で閉じます (失敗の理由はバーの［詳細］)
- ［隠す］を押すと、その起動が終わるまで出ません (起動は続きます)

### バーの位置

状態に合わせて自動で移動します。

| いつ | 位置 | 理由 |
|---|---|---|
| 起動直後（何も選んでいない） | **画面中央** | ランチャーが主役。探さずに見つかる |
| ツールを選んだあと | **左下** | 業務画面が主役。隅へ寄って邪魔をしない |
| ツールを終了して何もなくなったら | 画面中央へ戻る | |

1920×1080 での座標は次のとおりです（移動は 0.18 秒かけて滑らかに動きます）。

```
中央 : 980x56+470+512
左下 : 980x56+16+976
```

**手で動かすと、そちらが優先されます。** タイトルバーをドラッグすると位置を記憶し、
以後は自動で移動しません（動かすたびに戻されると使えないため）。
自動に戻すには、設定画面の「バーの位置」で **［自動に戻す］** にチェックを入れて保存してください。

画面構成が変わって（二画面を外した、解像度を変えた）バーが見えない場所に残った場合は、
次の起動で自動的に既定の位置へ戻ります。

位置と動きは `config/launcher.json` の `ui` で変更できます。

```json
"ui": {
  "bar_height": 56,
  "bottom_margin": 48,
  "edge_margin": 16,
  "position_idle": "center",
  "position_active": "bottom_left",
  "move_animation_ms": 180
}
```

| 項目 | 意味 |
|---|---|
| `position_idle` / `position_active` | `center` / `bottom_left` / `bottom_center` / `bottom_right` |
| `move_animation_ms` | 移動にかける時間。`0` で瞬間移動 |

### そのほかの設定 (`config/launcher.json`)

製品の既定値です。**ランチャーを新しい版に入れ替えると、このファイルも入れ替わります。**
現場で決めたツールの設定は、ここではなく[配布先フォルダ](#配布先フォルダを作る)に置いてください。

```json
"ui": {
  "health_poll_seconds": 5,
  "health_failures_before_dead": 3,
  "start_timeout_seconds": 90,
  "stop_timeout_seconds": 30
},
"browser": {
  "mode": "app_window",
  "preferred": ["edge", "chrome", "chromium"],
  "extra_paths": []
},
"logs": {
  "tool_log_max_mb": 5,
  "tool_log_keep": 2
}
```

| 項目 | 意味 |
|---|---|
| `ui.health_poll_seconds` | ツールの生存確認の間隔（秒） |
| `ui.health_failures_before_dead` | 何回続けて応答が無ければ「終了した」とするか |
| `ui.start_timeout_seconds` / `stop_timeout_seconds` | 起動・停止を待つ上限（秒） |
| `browser.mode` | `app_window`（閉じられる専用画面）/ `default`（既定ブラウザー） |
| `browser.preferred` | 探すブラウザーの順 |
| `browser.extra_paths` | 見つけられない置き方の端末で、実行ファイルを直接指定 |
| `logs.tool_log_max_mb` / `tool_log_keep` | ツール出力ログを退避する大きさと、残す世代 |

`health_failures_before_dead` を 1 にすると、スリープ復帰直後や重い処理中に
動いているツールを「終了した」と誤判定します。既定の 3 を下げないでください。

### ツールを増やす・減らす

**ランチャー本体のコードは書き換えません。** 増やす道が2つあります。

**① 端末で足す（設定画面）**

［設定］→ **［＋ ツールを追加］** → そのツールの起動ファイルを選ぶだけです。
隣の `config/app.json` からアプリID・表示名・ポートを読み取って埋めます
（読めなければ手入力）。減らすときは行の **［削除］** にチェックして保存します。

> アプリIDは起動確認の鍵なので、手で写すと 1 文字違いで永久に起動確認が通らなくなります。
> だから読み取ります。既存の行のアプリIDは変更できません（動いているツールを見失うため）。

**② 全端末に届ける（配布先フォルダ）**

1台で ① のとおり足してから、［設定］→ **「配布先フォルダを作る」** で作り直し、配り直します。
**すでに使っている端末にも次回起動で入ります**（その端末にまだ無いツールなので）。
（→ [配布先フォルダを作る](#配布先フォルダを作る)）

#### 数が増えたら

**登録できる数に上限はありません。** バーに並べきれなくなったら、入りきらないぶんは
自動で **［▼］** にまとまります。

```
画面が広いとき : [日報] [カレンダー] [看板] [総合ツール] [検査] [プレス] …
画面が狭いとき : [日報] [カレンダー] [看板] [総合ツール] [検査] [▼]
                                                            └ プレス / 塗装 / 組立
```

- 並び順は設定の `order_no` のままです（［▼］に回っても順番は変わりません）
- **いま使っているツールは必ずバーに出ます**（［▼］に隠れると、どれが動いているか見えなくなるため）
- ［▼］の中では、使用中に `●`、未設定に「（未設定）」が付きます

1920×1080 で12個前後、1366×768 で8個前後まではバーに並びます（表示名の長さによります）。

### 二重に起動しません

`Start.vbs` を素早く2回押しても、ランチャーは1つだけ起動します（2つ目は「すでに起動しています」
と出て終わります）。ツールのボタンを続けて押しても、`start.bat` が走るのは1回だけです。

**同じツールの画面が2枚開くこともありません。** 切り替えでは前の画面を閉じてから次を開き、
同じツールをもう一度押しても、画面がすでにあれば開き直しません。

> 業務ツールの作業状態はプロセスに1つしかないため、画面が2枚あると互いに上書きし合います。
> ランチャーは開く前に既存の画面を探すので、記録を失った状態でも2枚目を開きません。

ただし、ブラウザーに `http://127.0.0.1:8733/` を直接打ったり、ツールの `Start.vbs` を直接
実行したりすれば画面は増やせます。**ツールはランチャーから起動してください。**

### 止める

ランチャーの **[終了]** を押すと、業務ツールも止めるかどうかを聞かれます。

- **はい** … ツールも終了してランチャーを閉じる
- **いいえ** … ツールは動かしたままランチャーだけ閉じる
- **キャンセル** … 閉じない

ランチャーを使わずに止めるときは `stop.bat` を実行してください。

```
stop.bat            正常終了を要求して止める
stop.bat --status   いま何が動いているか見るだけ
stop.bat --force    実行中の処理を中断してでも止める
```

### バージョンを確かめる

ランチャーの版は4か所に出ます。

| どこ | 表示 |
|---|---|
| ウィンドウのタイトル（タスクバー・Alt+Tab） | `業務ツール統合ランチャー v1.0.0` |
| バーの右のバッジ | `v1.0.0`（押すとバージョン情報） |
| `start_debug.bat --check` | 一覧で出力 |
| 起動ログ | 起動のたびに1行 |

版の出どころは **`launcher/__init__.py` の `__version__`** ただ1つです。
設定ファイル（`config/launcher.json`）には置きません — 設定は端末ごとに書き換わるうえ、
壊れることもあり、**壊れたときに版まで分からなくなると、いちばん版を知りたい場面で答えが出ない**ためです。
版を上げるときはこの1行を書き換えてください。

バーの **`v1.0.0`** バッジを押すと、バージョン情報が出ます。

```
業務ツール統合ランチャー
v1.0.0
  アプリ本体: C:\業務ツール\ランチャー
  Python    : 3.11.5 (...\pythonw.exe)

業務ツール
  日報        動作中    3.0.0
              C:\業務ツール\日報
  カレンダー  版ちがい  3.1.0 → 動作中は 3.0.0
              C:\業務ツール\カレンダー
              ※古いプロセスが動いたままです。stop.bat で止めてから起動し直してください
  看板        未設定    —
  総合ツール  停止中    2.51.0
```

**2つの版を並べて出します。**

| 表示 | 出どころ | 意味 |
|---|---|---|
| 入っている版 | そのツールの `config/app.json` | いまフォルダーに置かれている版 |
| 動いている版 | `GET /api/health` | いま実際に動いているプロセスの版 |

食い違っていれば「版ちがい」と出ます。**「入れ替えたのに直らない」の典型的な原因**で、
古いプロセスが残ったままの状態です。`stop.bat` で止めてから起動し直してください。

停止中のツールも「入っている版」は分かります（起動しなくても `config/app.json` を読むため）。

［コピー］を押すと全文がクリップボードに入ります。不具合を知らせるときにそのまま貼れます。
コンソールで見るには `start_debug.bat --check` を実行してください。

### 起動しないとき

`start_debug.bat` を実行してください。コンソールを開いたまま、環境と設定の確認結果を表示します。

```
start_debug.bat            確認してから起動する
start_debug.bat --check    確認だけして終わる
```

ログは `%LOCALAPPDATA%\BusinessToolsLauncher\logs` にあります。

| ファイル | 中身 |
|---|---|
| `launcher_YYYYMMDD.log` | ランチャーの起動・停止・切り替え・エラー |
| `tool_<アプリID>.out.log` | 各ツールの `start.bat` が出力した内容 |

`launcher_*.log` は30日で消えます。`tool_*.out.log` は日付で分かれないため、
5MB を超えたら `.1` `.2` と退避します（`config/launcher.json` の `logs` で変更できます）。

## 配布する

### 設定はフォルダーと一緒に移動しません

［設定］で入れた値は、ランチャーのフォルダーではなく**各PCの利用者ごとの領域**に保存されます。

```
%LOCALAPPDATA%\BusinessToolsLauncher\data\launcher.db
```

あなたのPCで設定したフォルダーをコピーしても、配った先では**全ツールが「未設定」から始まります。**
同じPCでも、Windows に別の利用者でログインすれば別の設定になります。

**配った先でも最初から設定済みにするには、配布先フォルダを作ってから配ってください。**

| 置き場所 | 中身 | ランチャーを新しい版に入れ替えると |
|---|---|---|
| `config/launcher.json` | 製品の既定値 | 入れ替わる |
| **`distribution\`（配布先フォルダ）** | **現場の設定と管理者パスワード** | **残す**（上書きしない） |
| `%LOCALAPPDATA%\...\launcher.db` | その端末の設定（動作中の参照先） | 残る |

### 配布先フォルダを作る

1. 1台でランチャーを起動し、**［設定］** を開く（はじめてなら管理者パスワードを決めます）
2. 全ツールの起動ファイル・表示名・ポートなどを整え、実際に起動できることを確かめる
3. ［設定］→ **「配布先フォルダを作る」** を押す（画面の内容を保存してから作ります）
4. ランチャーのフォルダーの中に `distribution\` ができるので、**親フォルダーごと**配る

```
C:\業務ツール\                  ← この親フォルダーごと配る
├─ ランチャー\
│  └─ distribution\             ← 配布先フォルダ
│     ├─ settings.json          ツールの設定
│     ├─ password.json          管理者パスワードの照合値
│     └─ README.txt             このフォルダーの説明
├─ 日報\start.bat               → settings.json には "../日報/start.bat" と書かれる
├─ カレンダー\start.bat
├─ 看板\start.bat
└─ 総合ツール\start.bat
```

**起動ファイルは、ランチャーのフォルダーを起点にした相対パスで書きます**（既定）。
配った先で `C:\業務ツール\` に置いても `D:\Tools\` に置いても、同じ並びなら同じ設定で動きます。
全端末でまったく同じ場所に置くなら、［相対パスで書く］を外して場所そのままで書けます。
別のドライブにあるツールは相対にできないので、場所そのままで書き、そう知らせます。

| 書くもの | 書かないもの（端末ごとに違ってよい） |
|---|---|
| アプリID・表示名・並び順・起動ファイル・起動引数・ポート・起動確認の道・停止方法・［使う］ | 作業フォルダーの上書き、起動確認URLの差し替え、このPCのモード、バーの位置 |

> **配布先フォルダの中は手で書き換えないでください。** JSON はコメント（`//`）が書けず、`\` は2つ重ねる決まりがあり、
> 1文字の誤りで全体が読めなくなります。直したいときは［設定］から作り直してください。

### 配った先での読み込み — その端末にすでにある設定が優先

起動するたびに、配布先フォルダがあれば読み込みます。**その端末にすでにある設定が優先**で、
配布先フォルダから入るのは、**その端末にまだ無いもの**だけです。

配布先フォルダがあれば、**ツールの一覧は配布先フォルダのとおり**です。製品の既定値
（`config/launcher.json` の4ツール）は混ぜないので、配布元で消したツールは配った先にも出ません。

| 状況 | 振る舞い |
|---|---|
| 初めて起動した端末 | 配布先フォルダのとおりに入る |
| 配布先フォルダを置く前に一度起動しただけの端末（工場出荷のまま） | **配布先フォルダのとおりにそろえる。** 配布先フォルダに無いツールは外す |
| すでに使っている端末 | **その端末の設定のまま。** 配布先フォルダを作り直して配っても変わらない |
| その端末にまだ無いツール | 入る（5個目を足して配れば、使っている端末にも入る） |
| その端末で空欄の起動ファイル | 埋まる |
| 配布先フォルダの起動ファイルが、その端末に無い | 入れない（未設定のまま）。あとで置けば、次の起動で埋まる |
| その端末で削除したツール | 戻らない |
| その端末で［＋ ツールを追加］したツール | 残る（配布先フォルダに無くても消さない） |
| 配布先フォルダの設定が壊れている | その端末の設定のまま起動する（起動時に知らせる） |

**すでに使っている端末を、配布先フォルダの内容にそろえたいとき**は、その端末で
［設定］→ **「配布先フォルダの内容で置き換える」** を押します。

- 配布先フォルダに書かれている項目で上書きします（その端末で削除したツールも戻ります）
- 配布先フォルダに無いツールと、その端末に無い起動ファイルはそのままにします
- 置き換える前に、設定DBの控えを取ります

「工場出荷のまま」とは、起動ファイルが空で、表示名・ポート・起動引数・停止方法・［使う］を
既定値から1つも変えていない状態です。どれか1つでも変えてあれば、その端末の設定として残します。

同じPCでも、Windows に別の利用者でログインした人は、その人の最初の起動で配布先フォルダを読み込みます
（設定は利用者ごとに持つため）。

ランチャーを**共有フォルダー**に置いて複数のPCから使っている場合は、配布先フォルダも共有です。

### 管理者パスワード

**［設定］を開くときに尋ねます。** ライン作業者が起動ファイルをうっかり変えてしまうのを防ぐためです。

- はじめて［設定］を開いたときに決めます（4文字以上）。決めないと［設定］は開きません
- パスワードは配布先フォルダの `password.json` に入ります。**配ると全端末で同じパスワードになります**
- 変えるとき: ［設定］→ **［管理者パスワードを変える］**。変えたら `password.json` を配り直します
  （配布先フォルダを作り直しても、パスワードは変わりません）
- 3回続けて間違えると［設定］は開きません（開き直せば、また入力できます）
- パスワードそのものは保存しません。照合用の値（PBKDF2-SHA256）だけを保存します

> **これは誤操作を防ぐための鍵で、守りの固い鍵ではありません。**
> ランチャーのフォルダーに書き込める人は、`password.json` を消せば外せます。

**パスワードを忘れたとき**は、`distribution\password.json` を消してください。
次に［設定］を開いたときに決め直せます。ツールの設定は消えません。

### ランチャーを新しい版に入れ替えるとき

**`distribution\` フォルダーだけは残して**、ほかを入れ替えてください。
現場の設定と管理者パスワードが、そのまま引き継がれます。

### 配る前の確認

1. **配布先フォルダを作ったか** ── ［設定］の「配布先フォルダ」に件数と作った日時が出ます。
2. **配った先で `start_debug.bat --check`** ── 各ツールが `[  OK]` になっているか確認します。
   配布先フォルダにあるのに見つからないときは、想定していた場所も表示されます。
   「プロセスの照合」が取得できない端末は、下の「端末によって使えない機能」を見てください。

```
配布先フォルダ: C:\業務ツール\ランチャー\distribution
  設定: ツール 4件 / 2026-09-24 08:30:12 に LINE-PC01 で作成
  パスワード: あり
  その端末にすでにある設定が優先されます

  [未設定] 日報 (nlm.nippou-tool)
         起動: (未設定)
         配布先フォルダ: ../日報/start.bat
                       → C:\業務ツール\日報\start.bat (見つかりません)
```

### 端末によって使えない機能

ランチャーは「このプロセスは本当に自分のものか」を確かめるために、Windows の `wmic` か
`PowerShell` を使います。**両方とも使えない端末があります。**

- `wmic` … Windows 11 24H2 以降は既定で入っていません
- `PowerShell` … 工場の端末では一般利用者に禁止されていることがあります

両方使えない端末では、次のようになります。

| 機能 | 使えるか |
|---|---|
| ツールの起動・切り替え | ○ |
| **今回ランチャーが開いた画面を、切り替えで閉じる** | ○（開いたときの手がかりで閉じます） |
| `stop.bat` と停止要求でツールを止める | ○ |
| 前回のランチャーが開いた画面を閉じる | × |
| 記録を失ったとき、既に開いている画面を探し出す | × |
| PID でツールを止める（最後の手段） | × |

使えない機能はどれも「確かめられないものには触らない」側に倒れるので、**別のアプリを誤って
閉じることはありません。** 配った先の `start_debug.bat --check` に出ます。

```
プロセスの照合: 取得できません (wmic も PowerShell も使えない端末です)
  ランチャーが今回開いた画面は閉じられますが、
  前回のランチャーが開いた画面は閉じられません。
```

### 壊さないように

| ファイル | 注意 |
|---|---|
| `Start.vbs` / `start_debug.bat` / `stop.bat` | **CP932（Shift-JIS）のまま**保存してください。UTF-8 で保存し直すと現場で文字化けし、起動しなくなります |
| `config/launcher.json` | **UTF-8** の正しい JSON。コメント不可、パスの区切りは `/` |
| `distribution\` | **中を手で書かない。** ［設定］から作る。ランチャーを入れ替えるときも残す。Git には入れない設定（`.gitignore`）にしてあります（パスワードの照合値を含むため） |
| `launcher/__init__.py` | 版を上げるときは `__version__` の1行だけ |

配布物に入れなくてよいもの: `tests/`、`docs/`、`__pycache__/`（開発用）。

## 必要なもの

- Windows
- Python 3.9 以上(`Add python.exe to PATH` にチェックを入れてインストール)
- tkinter(Pythonインストーラの「tcl/tk and IDLE」。既定で入ります)

**追加パッケージはありません。** 標準ライブラリだけで動きます(`requirements.txt` を参照)。
各業務ツールが必要とする Flask などは、それぞれのリポジトリ側の話です。

## ファイル構成

```
python-business-tools-launcher
├─ Start.vbs             通常起動(利用者はこれだけ)     CP932/CRLF
├─ start_debug.bat       診断起動(コンソールあり)       CP932/CRLF
├─ stop.bat              業務ツールの停止                CP932/CRLF
├─ launcher.py           Python側の起動開始点
├─ launch_guard.py       ランチャー自身の多重起動防止
├─ app_manager.py        起動・切り替え・停止の順序
├─ process_manager.py    対象ツールの確認と安全な停止
├─ requirements.txt
├─ launcher/
│  ├─ app_config.py      設定とローカル領域
│  ├─ logging_utils.py   ログ初期化
│  ├─ health.py          起動確認 (GET /api/health)
│  ├─ browser.py         専用ブラウザー画面の開閉
│  ├─ version_info.py    どの版が入っていて、どの版が動いているか
│  ├─ tool_registry.py   ツール設定 (SQLite)
│  ├─ distribution.py    配布先フォルダの読み書きと管理者パスワード
│  ├─ admin_lock.py      ［設定］を開く前のパスワード確認の流れ
│  ├─ runtime_state.py   起動中のツールの記録
│  └─ ui/                tkinter。**ここだけが画面を知る**
│     ├─ bar.py          常駐ランチャーバー
│     ├─ settings_dialog.py  設定画面
│     ├─ password.py     パスワードの入力欄
│     ├─ version_dialog.py   バージョン情報
│     ├─ geometry.py     バーの幅と座標(tkinter非依存)
│     └─ theme.py
├─ config/launcher.json  アプリID・表示名・既定のツール定義 (製品の既定値)
├─ distribution/        配布先フォルダ (［設定］で作るとできる。現場のもの)
├─ docs/設計.md          設計の考え方と、要件との対応
└─ tests/                起動・切替・停止・多重起動防止の通し試験
```

実行時に増えるものは、アプリ本体ではなく `%LOCALAPPDATA%\BusinessToolsLauncher` に置きます。
共有フォルダーにランチャーを置いて複数人で使っても、利用者ごとの状態が衝突しません。

```
%LOCALAPPDATA%\BusinessToolsLauncher\
├─ runtime\   起動中のツールの記録・ランチャーのロック
├─ logs\      起動・停止・エラーの記録
├─ pycache\   Pythonのバイトコード
├─ cache\     再取得できる高速化用データ
├─ work\      一時ファイル
├─ backup\    設定DBの控え
├─ browser\   業務ツール画面の専用プロファイル(ツールごと)
└─ data\      設定DB本体(消すと設定が消えます)
```
