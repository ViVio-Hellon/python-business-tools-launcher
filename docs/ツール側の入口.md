# ツール側に用意してもらう入口 (ランチャー連携)

業務ツール統合ランチャーは、**各ツールの作り (EXE・VBS・BAT・Python・ブラウザー) を知らずに**
起動・起動確認・終了をするために、ツールが用意した「入口」を使います (要件定義「ランチャー連携」§3・§10)。

ツールの中身は変えずに、**起動ファイルと同じフォルダーにファイルを置くだけ**です。置いていない
ツールは、これまでどおりランチャーが補います (起動確認の URL・窓の検出・停止方法の自動選択)。
置いてあれば、**ランチャーの推測より入口を優先**します。

```
総合ツール\
├─ A.exe                  起動ファイル (PC ごとに［設定］でどちらかを選ぶ)
├─ A.vbs                  起動ファイル
├─ launcher_check.bat     起動確認の入口 ← 置く
└─ launcher_stop.bat      終了の入口     ← 置く
```

A.exe と A.vbs のどちらを選んだ PC でも、同じフォルダーの入口が使われます。

## launcher_check.bat (起動確認の入口)

ランチャーが**繰り返し実行**します (起動を待つあいだは約1秒ごと、動いているあいだは見回りのたび)。
終了コードで答えてください。

| 終了コード | 意味 | ランチャーの動き |
|---|---|---|
| `0` | 使える (起動完了) | 起動中の窓を閉じて「動作中」にする |
| `2` | 動いているが準備中 | 待ち続ける。動作中のツールなら「動いている」とみなす |
| それ以外 | 動いていない | 起動を待っているなら待ち続ける (上限まで)。動作中だったなら、何回か続けば「終了した」とみなす |

- **10 秒以内に終わってください。** 終わらなければ「確かめられない」として扱い、子プロセスごと止めます
- 最後に出力した1行を、起動中の窓に「準備の段階」として出します (任意)
- 画面 (コンソール) は出ません。`pause` は置かないでください (置いてもすぐ抜けます)

### 例 1: 決まったポートの Web ツール

```bat
@echo off
rem 0 = 使える / 2 = 準備中 / 1 = 動いていない
rem --noproxy: 社内のプロキシを通さない (通すと自分自身に届かない)
curl --noproxy "*" -fs --max-time 3 http://127.0.0.1:8700/api/health >nul 2>&1
if errorlevel 1 exit /b 1
exit /b 0
```

### 例 2: 役割でポートが変わる Web ツール (梱包資材総合ツールなど)

ポートを知っているのはツール自身です。ツールの中の仕組み (ロックファイル・状態表示の
コマンドなど) で確かめ、終了コードで返してください。

```bat
@echo off
rem ツール自身の状態確認を呼ぶ。終了コード 0/2/1 を返すようにしておく
python "%~dp0process_manager.py" --status --exit-code
exit /b %errorlevel%
```

## launcher_stop.bat (終了の入口)

ランチャーの［ツール停止］・終了時に実行します。ツールが**自分で後片付けして終わる**処理を書いてください。

- 終了コード `0` = 終了の手続きをした。止まったかは**起動確認の入口**で確かめます
  (起動確認の入口が無いツールは、終了コード 0 を信じます)
- 実行中の処理があるなど、止められないときは `0` 以外 (例: `1` = 処理中) で終わり、最後の1行に理由を
  書いてください。ランチャーは**待たずに**その理由を添えて「強制終了 (中断) しますか」を利用者に聞きます
- 利用者が「はい」を選ぶと、ランチャーは **`launcher_stop.bat --force`** で呼び直します。受け付けない
  ツールは無視してかまいません。それでも止まらなければ、ランチャーの止め方 (窓を閉じる・PID) で続けます
- 起動確認の入口は、**起動直後の数秒は `1` を返してもかまいません**。起動を待つあいだは上限まで待ち続けます
- **ほかのツールの Python・EXE を止めないでください** (要件 §12)

```bat
@echo off
rem 例: いまの stop.bat をそのまま使う
call "%~dp0stop.bat"
exit /b %errorlevel%
```

## 名前を変えたいとき・確認を URL でするとき: launcher.json (任意)

```json
{
  "check": "launcher_check.bat",
  "check_url": "http://127.0.0.1:8700/api/health",
  "stop": "launcher_stop.bat"
}
```

- `check` と `check_url` はどちらか一方 (両方あれば `check`)
- `check_url` は HTTP 200 で「使える」、JSON に `"ready": false` があれば準備中、つながらなければ
  「動いていない」。**この端末 (`127.0.0.1`) の URL だけ**です
- パスは `launcher.json` からの相対

## 確かめ方

ランチャーの［設定］で、そのツールの行に「ツールの入口: 起動確認 launcher_check.bat・終了 launcher_stop.bat」
と出れば、ランチャーは入口を見つけています。`start_debug.bat --check` の診断にも出ます。
